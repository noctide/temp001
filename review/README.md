# 审计文件夹（review/）

一个开发项目一个子文件夹（名字与 `projects.yaml` 的项目名相同），存**审核证据**：每次审核的结论、`tl check` 原始输出、测试输出、单独运行（`tl.py run <模块>`）的结果与截图、对拍结果。

- **只有架构能写**（执行 Agent 的允许路径里没有 `review/`，`tl check` 的范围检查会拦）。
- **和说明书的分工**：`plan/wp/<编号>.md` 末尾的"审核记录"是写给 Agent 看的返工意见；`review/<项目>/` 是留档的证据。两边都写，说明书里写结论和要改的，证据放这里。
- **每次审核一份文件**：`review/<项目>/<编号>-阶段<N>-<日期>.md`，内容按下面的格式；附件（截图、长输出）放同名文件夹。
- 每个项目的 `README.md` 是时间线：一行一次审核，链到那份文件。

## 单次审核文件格式

```
# <编号> 阶段 N · <日期> · 通过 / 返工
- 审的提交：<提交号>（分支 <项目>/<编号>）
- 环境：VM 克隆 / 本机；PostgreSQL 版本；是否装前端依赖
## 结论
（通过 / 返工；返工逐条：问题、怎么复现、怎么改——与说明书里写给 Agent 的一致）
## 证据
- tl check：（贴原始输出，或附件 tl-check.txt）
- 测试：pytest / vitest 的汇总行
- 单独运行：`tl.py run <模块> --smoke` 的输出；手动看过的页面截图
- 对拍 / 复现脚本：（如有）
```
