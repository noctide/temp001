> 版本：V1.0｜日期：2026-10-18｜状态：维护者已确认（设计页 sketch-backend-attendance v1，H 节 3 处 2026-10-18 "可以"）；数值为起点值，M2 实测后校准。
> 定位：把《考勤签到平台子方案》落成后端：数据怎么存、一条填报怎么走、时长怎么算、哪些放后台、用哪些平台底座、对外给什么。业务规则以子方案为准，本文不新增业务行为。
> 依据：考勤签到子方案全文；后端详细设计·总图、身份与权限、命令与任务、公共设施；实施路线 M2、D-04、D-07；ADR-031。

## 1. 组成

| 块 | 职责 |
| --- | --- |
| 签到与门禁 | 网页 / 手机 / 扫码签到，门禁记录导入（文件，以后适配器）。只是证据，不直接等于"正常出勤"（子方案 8） |
| 填报 | 员工或管理员代填：加班、请假、补签、外出……一次可交多条 |
| 排班 | 草稿 → 检查 → 发布成不可改的版本；调班 = 发新版本（子方案 7） |
| 区间与规则引擎 | 纯函数：有效时长 = 工作区间并集 − 休息区间并集；再按日期属性、班次、正常区间切成互斥类别；同一秒只进一类（子方案 10） |
| 额度账 | 每人每月一本账：提交时占、确认时转正、退回撤回释放（第 6 节） |
| 异常 | 缺卡、迟到早退、未排班出勤、疑似漏报；自有处理状态，与平台运行告警、通知分开（子方案 13） |
| 正式结果 | 管理员处理即确认（首期无审批流程）；更正 = 新版本（子方案 12） |
| 提报批次 | 导出外部模板或直接标记已提报；批次不可改、可撤销、可出更正批次（子方案 14、20.5） |
| 数据出口 | 事件 + 增量出口；分析在数据处理与可视化做（子方案 15） |

## 2. 数据怎么存

schema `attendance`，只有考勤模块的数据库账号能写。

| 一组表 | 存什么 | 规矩 |
| --- | --- | --- |
| 配置：类型 · 快捷时间 · 班次 · 规则集 · 出勤方案 · 签到策略 · 导出模板 | 每类"定义"+"版本"两张表；适用范围、优先级、有效期 | 草稿 → 校验 → 发布不可改 → 按有效期启用；同范围同优先级有效期重叠拒绝发布；数值类（宽限、补签上限、疑似漏报阈值）从业务参数读 |
| 排班草稿 · 排班版本 · 排班明细（人 × 业务日） | 班次与实际计划区间 | 发布后不改；调班生成新版本并记原因、谁改、何时生效；当前生效版本用指针另存 |
| 签到事件 | 来源、来源事件编号、发生时间、收到时间、人、可信度 | 只追加；（来源, 来源事件编号）唯一；补签、更正另记一条指向原条 |
| 填报 · 填报修订 | 原始区间、休息区间、有效区间、类型、事由、人员快照 | 每次提交 / 重交 / 更正一个修订 |
| 处理记录 · 正式结果版本 | 绑定修订号；各类时长（秒）与证据引用、所用版本 | 修订变了原确认失效；结果只增版本 |
| 额度 · 额度流水 | 每人每月一行：上限、已占、已认定；每笔占用 / 转正 / 释放一行流水 | 流水只追加，余额可由流水重算对账 |
| 异常 | 类型、人、范围、证据、处理状态、是否仍存在 | 去重指纹 = 人 + 规则 + 时间范围 + 输入版本 |
| 期间 · 提报批次 · 批次条目 · 计算记录 | 月份开 / 结账；批次固定所用修订、结果、模板版本，文件在公共文件服务；每行追到源填报 | 批次不可改；撤销写原因；外部状态与"已下载"分开 |

时间存 UTC（timestamptz），业务日另存；区间一律半开 [start, end)；时长存整数秒，小时只是显示；人员只存编号 + 当时的姓名、工号、部门快照（人员主数据归身份与权限）。

## 3. 一条填报的一生

1.  **草稿**：考勤表点格子存草稿，不占额度。
2.  **提交（一个事务）**：服务端重算时长（不信页面）→ 查规则（超上限只标不拦，子方案 8）→ 占额度 → 写修订 → 事件 → 处理人待办 → 出勤明细。
3.  **处理（一个事务）**："标记已提报"或"只记录" = 确认，生成正式结果版本，额度从"已占"转"已认定"；"退回" = 驳回，释放额度（子方案 12、20.5）。
4.  **提报**：导出文件或直接标记 → 提报批次；外部状态单独记。
5.  **更正**：新修订；已提报的进"需重报"，同步后生成关联原批次的更正批次。

并发：填报修订带修订号，后到的收到 `RESOURCE_VERSION_CONFLICT`；额度账"每人每月一行"在提交和确认时加锁，两条并发填报不能合计绕过额度。重复点击：用命令与任务的防重复编号，拿回第一次结果，不重复占额度。

## 4. 时长怎么算

一组纯函数：不读库、不读时钟，输入一样结果一样。有效 = 工作区间并集 − 休息区间并集（只扣与工作重叠的部分，重叠休息不重复扣）；与正常区间求交得正常时长，其余按规则归入工作日 / 休息日 / 节假日加班。每次计算记下排班、规则、日历、计算程序版本、取整策略与命中规则，可解释、可按原规则重现、可按新规则模拟（模拟不改正式结果）。规则是登记好的确定性代码；管家可起草规则草案，不能临场解释制度后裁决。验收用子方案 10.1 三例与 21 节。

## 5. 后台任务

| 事 | 怎么跑 | 何时 |
| --- | --- | --- |
| 发布排班前检查 | 重道：连续出勤、6休1、班次间隔、额度预估；看跨月边界，未来未排标"检查不完整" | 点"检查"或"发布" |
| 导出提报文件 | 重道：按模板生成 Excel 存公共文件服务；工号保留前导零，文本不当公式 | 点"导出" |
| 疑似漏报、缺卡、计划加班到期 | 轻道定时：开 / 关异常，限频提醒本人与管理员 | 每天 06:30、13:00（业务时区） |
| 门禁记录导入 | 轻道：按来源事件编号去重，写签到事件，只重算受影响的人和天 | 上传时；适配器按其间隔 |
| 今日出勤统计 | 不放后台：实时有界查询，按管理范围裁剪；首页卡片缓存 30 秒（键含范围） | 打开时 |
| 历史重算 | 重道：只模拟；正式修正走更正命令 | 管理员发起 |

## 6. 已确认的决定（2026-10-18）

| # | 决定 | 备注 |
| --- | --- | --- |
| 1 | 待确认的加班占额度：提交即占，退回 / 撤回释放，确认转为已认定 | 超额度只标不拦（子方案 8 / 11） |
| 2 | 跨夜、跨月加班按业务日（排班那天）归月 | 做成配置，外部要求拆开时换版本 |
| 3 | 原始签到事件与出勤明细在线保留 3 年，到期按月归档为文件 | 部署参数；正式结果、填报修订、提报批次一直保留 |

已定默认值：时长整数秒；6休1 / 7 天上限出厂"只提示不阻断"（D-04）；外部模板标"未验证"（D-07）；疑似漏报每天 06:30、13:00；今日出勤卡片缓存 30 秒；一次提交上限 100 条（业务参数）；发布检查超时 5 分钟；提报文件单文件 ≤ 20000 行。取舍见 ADR-031。

## 7. 用平台底座的什么

-   **身份与权限**：人、部门、任职只读引用；`check` 判能不能，`filter` 取能看哪些（员工 = 本人；考勤管理员 = 管理范围；部门负责人 = 本部门）；登记权限字段"所属部门"、可遮挡列"事由"。
-   **命令与任务**：子方案 16 节的能力全部登记；发布排班、导出、批量处理走"准备 → 看影响 → 提交"，其余一步提交；后台任务、定时、发件箱用它的。
-   **公共设施**：审计同事务写；文件（模板、提报文件、附件）；通知（签到提醒、异常提醒，受免打扰与合并）；待办（待处理的填报，先办先得）；文案 `attendance.*`。出勤明细由事件与审计生成，不是第二份数据。

## 8. 对外接口

-   `attendance.api`：`today_summary(范围)`（首页、工作台卡片）、`my_summary(人)`（工作台"我的考勤"）、`schedule_of(人, 日期段)`（表单"工作日数"等）。写入一律经登记能力（如 `attendance.declaration.submit`），表单流程、自动化、管家不另开后门。
-   事件（契约 event-types.json）：`attendance.schedule.published`、`attendance.declaration.submitted|confirmed|rejected|withdrawn|corrected`、`attendance.result.versioned`、`attendance.alert.opened|cleared`、`attendance.batch.generated|revoked`、`attendance.period.closed`。带变更序号，更正带"更正自"，消费方按事件编号幂等。
-   状态机（契约 state-machines.json）：填报、异常处理、提报批次生成、期间。

## 9. 建设顺序（考勤开发项目的阶段，每阶段架构审核一次）

1.  配置版本 + 区间 / 分类引擎（纯函数，先跑通子方案 21 节计算类验收）
2.  签到事件 + 签到页接口 + 今日出勤统计
3.  填报 → 处理 → 正式结果 → 额度账（含并发测试）
4.  排班草稿 / 检查 / 发布 / 调班
5.  异常与疑似漏报定时任务
6.  提报批次与导出、更正批次
7.  前端：签到、考勤表两层、提报、出勤明细、异常、类型与规则（按高保真 Attendance.html）

## 10. 给执行 Agent 的技术细节

-   目录：`domain/interval.py`（区间运算，秒级整数）、`domain/classify.py`（分类、跨夜业务日）、`domain/rules/`（每条规则一个确定性实现 + 版本号，输出命中证据）、`domain/quota.py`、`domain/states.py`（对照契约状态机测试）；`store/` 把 `filter` 翻译成参数化 SQL；迁移版本表 `attendance_alembic`。
-   约束：区间两列 + CHECK start < end；排班同人同业务日有效版本唯一；签到事件（source_id, source_event_id）唯一；填报修订（declaration_id, revision）唯一；额度账（person_id, quota_month）一行，提交 / 确认时 `SELECT … FOR UPDATE`。
-   时长计算用基于性质的测试（随机区间：结果不为负、不超过工作区间总长、分类互斥且合计等于有效时长）。
-   测试人员只用合成人设表。
