# Titanloom · 后端详细设计 · 表单平台（M2）

> 版本：V1.0｜日期：2026-10-18｜状态：维护者已确认（设计页 sketch-backend-forms v1，H 节 3 处 2026-10-18 "可以"）；数值为起点值，M2 实测后校准。
> 定位：把《表单平台子方案》阶段一落成后端：定义与记录怎么存、一次提交怎么走、公式怎么算、流程与导入怎么做、对外给什么。业务规则以子方案为准，本文不新增业务行为。
> 依据：表单平台子方案全文；后端详细设计·总图、身份与权限、命令与任务、公共设施；实施路线 M2；ADR-032。

## 1. 组成

| 块 | 职责 |
| --- | --- |
| 定义 | 表单、字段、分区与显示条件、公式、每步字段权限、流程、HTML 组件版本、导入配置；草稿只有作者可见，发布前检查（子方案 26.3.4）通过才能发布成不可改的版本 |
| 命令链 | 授权 → 记录可见范围 → 本步字段权限 → 服务端重算公式与显示条件 → 校验 → 写修订 → 推进流程 → 待办 / 通知 → 审计，同一事务（子方案 12.3） |
| 公式引擎 | 自写解析器 + 白名单函数，不用 eval；有预算（子方案 7、20） |
| 流程引擎 | 最小状态机：开始 · 审批 · 办理 · 分支 · 并行 · 等待 · 自动操作 · 结束（阶段一先做开始、审批、办理、排他分支、退回、结束） |
| 记录与修订 | 每次正式动作一个修订；字段来源可查（子方案 13、16） |
| 导入 | Excel / CSV / 粘贴：逐行校验、只提交通过的行（子方案 6） |
| 记录页 | 按"谁能看记录"裁剪；导出超过 5000 行转后台（子方案 26.6） |
| 数据出口 | 发布时自动登记，按修订增量（子方案 18） |

## 2. 数据怎么存

schema `forms`；关系核心 + JSON 内容 + 按需生成列索引；不为每张表单建表（子方案 9.2）。

| 一组表 | 存什么 | 规矩 |
| --- | --- | --- |
| 表单 · 表单版本 | 负责人、分类；版本冻结字段、分区与条件、公式、字段权限、流程、组件版本、导入配置 | 草稿一行可改，发布 = 新的不可改版本；运行中的记录绑定开始时的版本 |
| 字段 | 稳定字段编号 + 显示名（中英）+ 类型 + 设置 | 公式、条件、组件存字段编号，改名不受影响（FW18） |
| 记录 | 编号（如 FM-0031-000128）、表单、版本、显示标签、提交人、所属部门 / 项目、业务时间、当前修订号、内容（jsonb） | 所有表单共用；表单声明的常用筛选字段建生成列 + 索引（每张表单最多 8 个） |
| 修订 | 动作、谁、代谁、何时、内容快照、与上一版差异、理由（更正必填）、字段来源 | 只追加；作废也是修订 |
| 附件引用 | 记录、修订、字段、用途；文件在公共文件服务 | 按引用鉴权下载 |
| 流程实例 · 办理任务 | 当前节点；派给谁 / 实际谁办 / 代办依据；办理人解析结果与时间 | 组织变化不改历史（FW08） |
| 导入批次 · 导入行 | 文件指纹、导入配置版本、逐行状态与原因、生成的记录 | 同文件同业务键不重复进（FW05） |

## 3. 一次提交怎么走

1.  草稿存服务端，换设备可接着填，不形成修订；停止输入 2 秒自动保存。
2.  提交（一个事务）：能不能填 → 本步可填字段 → 服务端重算公式与显示条件（客户端值不采信，FW15）→ 只校验显示分区的必填 → 写记录与修订 → 流程推进 → 待办 → 审计 → 事件。
3.  审批 / 办理：同意或完成 = 新修订，流程往下；退回须写意见，重交 = 新修订（FW03）。
4.  更正：按"谁能改 / 什么时候能改"；审批中的须先撤回；改后按设置重走流程或只通知（子方案 26.6）。

没有流程的表单提交即生效，不建流程实例（FW20）。连续登记每条一次提交，"撤回当天的" = 作废修订。并发：带"我看到的版本"，后保存的拿到冲突并逐项选择（FW02）。

## 4. 公式与条件

一种公式语言：设计器写 `天数差(「结束日期」, 「开始日期」) + 1`，保存为"规范函数名 + 字段编号"的语法树。首批函数照子方案 26.4。浏览器算只为即时显示；提交以服务端为准。

后端（Python）与前端（TypeScript）各一个解释器，但**函数清单、语法与每个函数的测试用例只有一份**：`packages/contracts/expressions/`。两边测试读同一批用例，任何一边结果不同即不通过（开发项目划分规范 5.5）。

预算：一次计算 10 ms、引用基表 20 次、依赖深度 32（业务参数）；循环依赖发布前拒绝（FW11）。

## 5. 流程、导入、记录页

-   **办理人**：个人 / 分组（先办先得）/ 按关系（问身份与权限）/ 按字段；解析结果存进任务；找不到转表单负责人。
-   **期限与等待**：用命令与任务的定时；到点提醒、转负责人或自动同意（按节点设置）。
-   **自动操作**：调其他模块登记的能力；重试、失败不改变审批结果。
-   **导入**：上传到文件服务 → 轻道任务解析（≤ 500 行在请求里返回预览，单批上限 5 万行）→ 逐行校验 → 页面里改坏行 → 每行一个命令、逐行返回结果（FW04、FW09）。
-   **记录页**：可见范围翻译为身份与权限的数据条件；敏感字段整列不下发；游标分页；导出 > 5000 行转后台，完成进待办；批量办理一次最多 200 条，逐条结果。
-   **功能开放**：`forms.create`（新建表单）、`forms.publishAll`（发布给全员填），即子方案 15.1 的两项（编号与模块名对齐）。

## 7. 对外接口

-   `forms.api`：`submit_record(表单, 内容)`（管家替你填草稿、自动化写入走同一命令）、`get_record(编号)`（按调用者权限）、`list_forms(我能填的)`（首页快捷导航、工作台）、待办办理能力。
-   事件（契约 event-types.json）：`forms.form.published|disabled`、`forms.record.submitted|corrected|voided|withdrawn`、`forms.workflow.node_entered|node_completed`、`forms.import.completed`。
-   增量出口（M3 数据处理需要，后续阶段补）：`export_changes(after_seq, limit)` 按变更序号返回记录的变化（含更正、作废），只给数据处理的服务身份（后端详细设计·数据处理 11）。
-   状态机（契约 state-machines.json）：办理任务。

## 8. 建设顺序（表单开发项目的阶段，每阶段架构审核一次）

1.  字段与表单定义、草稿 / 发布 / 版本、发布前检查
2.  表达式与显示条件（后端 + 前端，同一批用例）
3.  记录、修订、提交 / 更正 / 作废、并发、字段来源
4.  最小流程：开始、审批、办理、排他分支、退回、结束；办理人解析；待办
5.  Excel / CSV / 粘贴导入
6.  记录页查询、可见范围、导出
7.  前端：表单列表、设计器两步、填写三种方式、记录页（按高保真 Forms / FormDesigner / FormFill / FormRecords）
