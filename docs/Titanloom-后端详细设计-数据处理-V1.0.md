## 1. 组成

页面上的"接入 / 模型"在后台合称流水线（Pipeline，kind = ingest / model），同一套运行机制（子方案 7）。

| 块 | 职责 |
| --- | --- |
| 来源与批次 | 上传 Excel / CSV（原文件在公共文件服务）、平台模块（考勤、表单）的事件 + 增量出口、已有连接（M3 只留口子）。每次进来一个批次：编号、原文件、内容哈希、行号、水位 |
| 基表 | 业务人员维护的分类、映射、系数、日历表；草稿 → 检查 → 发布不可改的版本，带有效期（子方案 6.1） |
| 接入 | 原始层 → 清洗步骤 → 标准表；接入环节的问题行进隔离区 |
| 模型 | 标准表 + 基表 + 别的数据集 → 关系 → 指标与维度（语义层，子方案 12.5）→ 要发布的数据集 |
| 运行 | PipelineRun 的运行、质量、发布分开记（子方案 15.1）；JobRun 只管后台跑完没有 |
| 质量与隔离区 | 通过 / 告警 / 阻断；隔离行修补后回流重算（子方案 10） |
| 数据集版本 | 只增不改；新版本只存变化的行；指针切换即发布；数据代次与分区代次 |
| 受控只读查询 | 别的模块拿数的唯一出口（能力契约 9） |
| 血缘与图谱 | 发布时记血缘；使用方登记；图谱快照（子方案 11） |

## 2. 数据怎么存

schema `dataproc`，只有数据处理的数据库账号能写；别的模块不读任何一张表。

| 一组表 | 存什么 | 规矩 |
| --- | --- | --- |
| 来源 · 批次 | 原文件引用、内容哈希、行数、上传人、水位（平台来源记变更序号） | 只增不改；同哈希 + 同期间 + 同导入方式提示"可能重复导入"由人选（子方案 10.2） |
| 原始行 | 每个接入一张：批次、工作表、物理行号、原单元格（文本）、行哈希 | 只有接入器写，人不能改；COPY 批量写；在线 90 天，之后从原文件重放 |
| 标准表 | 每个标准表一张物理表，按接入版本声明的类型建；每行带来源批次与行 | 结构变了建新表（结构版本），旧表留到没人用；可由原始层重新生成 |
| 接入 · 模型 · 版本 · 草稿修订 | 版本 = DAG：节点（算子 + 精确实现 + 摘要 + 参数）、关系、指标与剔除规则（分开记版本）、维度、质量规则、发布规则 | 发布钉死实现，不用 latest；改了出新版本，只影响下一次运行；草稿带修订号防覆盖，个人草稿可直接删除 |
| 基表 · 基表版本 · 导入方案 · 用法绑定 | 按月维护（业务样子）与计算用长表（发布时生成）；用法绑定 = 业务日期 → 基表版本 | 发布后不改；长表"同一键同一天只有 1 条"由数据库排他约束兜底；外部权威来源只读引用 |
| 数据集 · 版本 · 行表 · 分区 | 行表每行带"从第几版起有效、到第几版失效"；当前版本指针、数据代次、按业务月份的分区代次与是否已关账 | 新版本只写差异；指针、代次在一个事务里改 |
| 修订版 | 并列的一整份结果 | 负责人"采用"后才成为正式新版本 |
| 快照 | 数据集 + 版本号 + 原因 | 被引用的版本永不清理 |
| 查询定义 · 字段标识 · 字段绑定 | 指标 + 维度 + 可筛选声明；FieldRef 目录；数据集字段 → FieldRef | 绑定由负责人手动做、随下一版生效（子方案 12.6） |
| 运行 · 节点运行 · 质量结果 · 隔离行 · 诊断 · 血缘边 · 使用方 · 图谱快照 · 查询缓存 | 见第 3、6、7 节 | 运行、隔离行、诊断只增；修补另记，原值不丢 |

**只存变化的行**：读第 v 版 = `_v_from ≤ v 且（_v_to 为空或 > v）`。新一版按行键与行哈希比出差异：变了的旧行标"到第 v 版"、插新行"从第 v 版"；没变的不动；完全无变化不出新版本、代次不变。由此：快照 = 记一个版本号；回退 = 出一个内容等于目标版本的新版本（只写差异），代次 +1，页面写"回到第 N 版"，历史保持线性；回补只重算受影响的月份。

时间存 UTC（timestamptz），业务日期另存；区间一律半开；精确数值 numeric、对外字符串编码；人员只存编号与快照。

## 3. 一次运行的一生

例：周宁上传 9 月工时补传文件，「工时效率模型」跟随重算，发布「月度工时汇总」。

1.  **上传（同步）**：文件进公共文件服务 → 登记批次 → 立即返回。
2.  **接入运行（重道）**：文件解析器插件 → COPY 写原始行 → 清洗算子 → 校验 → 问题行进隔离区 → 写标准表。
3.  **通知下游（轻道）**：接入完成 → 订阅它的模型在 10 分钟内合并成一次运行排队。
4.  **模型运行（重道）**：推导受影响的业务月份 → 按拓扑序算节点，每个节点做完存检查点 → 关系没对上 / 对上多条按该关系设置（默认隔离区）→ 指标 → 与当前可见行比出差异。
5.  **质量门禁**：阻断 → 不发布，旧版继续可查；告警 → 照发并标注。
6.  **发布（一个事务）**：写差异行 → 新版本 → 指针切换 → 代次 +1 → 受影响分区代次 +1 → 血缘边 → outbox `data.dataset.generation_changed` → 审计。

**三个维度**按子方案 15.1 与契约 pipeline-run：运行（accepted / running / reconciling / succeeded / failed / canceled / timed_out）、质量（not_evaluated / passed / warned / blocked）、发布（not_applicable / not_published / published / rolled_back / unknown）。JobRun 成功不改变任何维度；阻断必不发布（ADR-012）。

**断点与核对**：租约过期后重新领取，从最后完成的节点续做（检查点在临时表，丢失则重算该节点）；发布是单事务，不会出现半个版本；发布结果不确定时进待核对，核对方法 = 查是否存在该运行写的版本。

**并发**：同一模型同时只一个正式运行；运行中又有新数据 → 排一次跟随运行（只一次）。重复点击由命令防重复编号拿回同一运行。考勤、表单提交不等待数据处理。

## 4. 基表：版本、有效期、怎么生效

发布时"怎么生效"必须选（10-06 已定），没有默认：

| 选 | 后台做什么 |
| --- | --- |
| 只影响以后 | 用法绑定加"发布当天（业务日）起用新版"；之前的日期继续用旧版，以后重算也不变；不排运行 |
| 回补历史 | 用法绑定改为"从所选日期起用新版"（默认 = 改动里最早的生效日）→ 给受影响的模型排完整运行，只算该日期之后的月份 → 新版本 |
| 另出修订版 | 不改绑定；按"假如从某日起用新版"跑一次存成修订版，可对比，负责人采用后才进正式版本 |

**回补碰到已关账的月份（K-2，按建议）**：允许。准备阶段列出会改到的已关账月份与受影响的看板、接口，负责人确认；提交时**先自动给这些月份当前的版本建快照**（原因"回补前 · 日期"），再回补；发布后通知使用方。分区"已关账"来自来源模块的期间结账事件（如 `attendance.period.closed`）或负责人手动标注。

发布前检查（键重复、有效期重叠拦；下游兼容只提醒）在主程序同步跑，超过 5 万行转重道。导入 Excel 走重道，结果合进草稿，不直接发布，文件里没有的行不自动删除。

## 5. 算子：按插件 B1 契约登记

-   数据处理清单声明扩展点 `dataproc.operator@1`。每个算子 = 契约（输入输出字段、参数、确定性、能否按分区增量、错误码、字段血缘推导方式）+ 一个或多个实现（engine sql / polars、摘要、预算档）。内置算子同格式登记，标"官方内置"。
-   流水线版本钉"契约版本 + 实现 + 摘要"；换实现不改 DAG 核心（插件 B1 出口）。
-   **SQL 实现**（在 PostgreSQL 里算，模型几乎全用它）：关系（等值、复合键、按日期取有效）、映射、筛选、去重、聚合、窗口、指标与剔除、宽表转长表、节假日区间扣除（区间集合运算，重叠只扣一次）。
-   **Polars 实现**（重道子进程、分块）：大文件接入的清洗（选列改名、类型转换、格式校验、去重）与列画像。
-   同一算子有两种实现时用同一份用例对拍，逐行一致才能登记。停用 Polars：依赖它的接入运行失败并说明原因，已发布数据集照常可查。
-   外部服务、原生算子、个人 SQL / Python：契约字段保留，不实现；个人代码以 G-ISO 为前提（ADR-016，最早 M6 后）。

## 6. 受控只读查询

`POST /api/v1/queries/{queryId}/execute`（能力 `titanloom.data.query.execute`，能力契约 9.1）：

1.  查询定义 → 数据集 → 当前指针或快照指定的版本；
2.  `access.check`；行范围 `access.filter` → `access.api.sql.to_sqlalchemy`（字段名 → 列由本模块 store 传入）；列遮挡；
3.  只收已声明的 FieldRef 筛选，区间左闭右开，相对日期由服务端按业务时区解析；
4.  按"指标 + 维度 + 粒度"生成参数化 SQL 在库内聚合，比率按汇总后的分子分母重算；
5.  `shape = page`：游标分页、每页 ≤ 1000；`shape = aggregate`：一次返回，上限业务参数 `viz.chart.maxRows`，超限返回 `QUERY_BUDGET_EXCEEDED` 并给出办法，不截断；
6.  返回版本、代次、质量、数据时间；精确数字用字符串。

**缓存**：键 = 查询版本 + 形状 + 规范化筛选与参数 + 权限范围摘要 + 所覆盖月份的分区代次（覆盖不到分区时用数据集版本）。只有那个月数据变了分区代次才 +1，所以已关账月份长期命中、补录后自然失效，不需要专门清缓存。内存 LRU 32 MB；全部月份已关账的结果另存数据库（上限 256 MB）。

**不挤占业务写入**：查询专用连接池 3 条、等 2 秒，排不上返回可重试错误；只读角色单句 10 秒、work_mem 16 MB。全部导出走后台导出任务。管家取数同走此路，只拿结果与汇总（能力契约 9.3）。

## 7. 血缘、使用方、图谱

-   **血缘**（发布同事务写）：版本 ← 模型版本（实现摘要）← 标准表 ← 批次；← 基表版本（按用法绑定的日期段）；← 上游数据集版本。字段级只记能证实的映射（改名、选列、关系键、可解析的指标公式），其余标"未知 / 部分"。
-   **使用方**：可视化（保存看板时）、首页卡片、对外接口、自动化调用 `register_consumer` 登记；查询日志里出现但没登记的标"观测到、未登记"。
-   **图谱快照**：轻道在运行结束、发布、使用方变化时更新，页面直接读。接入失败 → 下游标"在用旧数据"并链到失败运行；无运行信息显示"未知"。

## 8. 后台任务

| 事 | 怎么跑 | 何时 |
| --- | --- | --- |
| 上传解析 + 接入运行 | 重道：子进程 512 MiB、分块 | 上传后；接入计划（手动 / 每天 / 每 15 分钟） |
| 模型试运行 / 完整运行 / 回补 / 修订版 | 重道：SQL 在库里算，子进程调度与存检查点；最长 30 分钟 | 点按钮；上游完成后跟随；模型计划（默认每天 06:00） |
| 样例预览 | 不放后台：主程序同步、SQL 实现、每输入抽 1000 行、结果 200 行、5 秒 | 点"预览结果" |
| 基表发布前检查 | 同步；超 5 万行转重道 | 点"检查" / "发布" |
| 基表导入 Excel | 重道 | 点"导入" |
| 考勤、表单变更拉取 | 轻道记"有新数据"，10 分钟内合并成一次接入运行（重道），按变更序号增量拉 | 事件到达时 |
| 隔离区回流 | 回流批次 → 只重算受影响月份（重道）→ 按模型发布规则发布 | 修补提交；基表发布后"等基表"的行自动重验 |

| 查询 | 实时有界；全部导出走重道 | 打开时 |

## 9. 已确认的决定（2026-10-20）

| # | 决定 | 备注 |
| --- | --- | --- |
| 1 | 保留期：原文件 3 年；原始行在线 90 天后从原文件重放；数据集版本在线 1 年，被快照引用的与每月最后一版永久；更早版本只留计算证据 | 都是部署参数 |
| 2 | 回补历史可改已关账月份：先列影响并由负责人确认，提交时自动给原数字建快照，发布后通知使用方 | 不设第二位批准 |
| 3 | M3 验收基表：职业分类（按月宽表、按日期取有效、例外有效期）+ 系数（复合键）；节假日区间扣除算子同期交付，用合成节假日表测 | D-05 结清；真实基表盘点留到公司使用环节 |

已定默认值：版本差异存储、回退 = 新版本；按业务月份分区重算；样例预览同步 5 秒；单次运行 30 分钟、子进程 512 MiB、运行角色单句 10 分钟 / work_mem 64 MB；关系行数膨胀估算超 3 倍先拦；隔离行超 1% 阻断（可改）；跟随运行 10 分钟合并；模型计划默认每天 06:00；查询连接池 3、单句 10 秒；缓存内存 32 MB + 库内 256 MB；草稿每 10 秒自动保存、留 50 条或 30 天；检查点运行结束或 7 天后清；D-11 暂用服务端分页表格；单文件 ≤ 50 MB、≤ 100 万行。取舍见 ADR-034。

## 10. 用平台底座的什么

-   **身份与权限**：资源类型数据源、接入、模型、基表、数据集、查询；`check` / `filter` / `to_sqlalchemy`；权限字段在数据集上声明（如 `fld_department`）；功能 `data.conn`（出厂指定的人：信息部）、`data.upload`（G-ISO 前不开放）。
-   **命令与任务**：写操作全部登记为能力；完整运行、发布、回补、回退、采用修订版走"准备 → 看影响 → 确认 → 提交"；改草稿、预览一步提交。运行 = 一个 PipelineRun + 若干重道 JobRun，核对方法由本模块提供；模型计划用定时规则；事件用发件箱。
-   **公共设施**：文件（原文件、错误报告、导出）；审计（发布、回退、改口径、绑定字段同事务写）；通知与待办（隔离区待修补、质量阻断、在用旧数据 → 负责人）；文案 `dataproc.*`；搜索（基表、数据集、字段）。
-   **插件宿主**：算子扩展点；复用 M1 的文件解析器（Excel / CSV）。

## 11. 对外接口

-   `dataproc.api`：`execute_query`、`describe_dataset` / `describe_query`（字段、FieldRef、可筛选声明）、`register_consumer`、`create_snapshot`。数据服务（外部调用方的限流、认证、废弃窗口）M3 只留口子。
-   事件（契约 event-types.json）：`data.dataset.generation_changed`、`data.dataset.stale`、`data.run.finished`、`data.reference.published`、`data.quarantine.opened`、`data.quarantine.resolved`。只带编号、版本、代次，不带数据行。
-   命名：能力、事件、功能统一用 `data.` 前缀；文案命名空间 `dataproc`；查询能力沿用能力契约的 `titanloom.data.query.execute`。
-   **需要考勤、表单补的增量出口**：`export_changes(after_seq, limit)`，按变更序号返回正式结果 / 记录的变化（含更正、作废），只给数据处理的服务身份。M3 开工时用合成数据的桩，考勤、表单在各自后续阶段补上（见两份后端设计第 8 / 7 节）。

## 12. 建设顺序（数据处理开发项目的阶段，每阶段架构审核一次）

1.  存储骨架 + 基表：定义、草稿、导入方案、宽表 → 长表、发布前检查、用法绑定与三种生效方式
2.  接入：来源、批次、原始行、清洗算子（SQL + Polars 对拍）、标准表、画像、接入环节隔离区
3.  模型与运行：DAG 版本、关系 / 指标 / 剔除、PipelineRun 三维度 + JobRun、检查点、预览 / 试运行 / 完整运行、质量门禁
4.  数据集版本：差异存储、原子发布、回退、修订版、快照、代次与分区代次、关账回补自动快照、事件；考勤 / 表单增量拉取（桩）
5.  受控只读查询：语义层聚合、可筛选声明、行列权限、上限、缓存
6.  血缘、使用方、影响分析、图谱快照；隔离区修补与回流
7.  前端：图谱、接入、模型、基表、数据集、隔离区、运行（按高保真 Pipeline.html）

## 13. 给执行 Agent 的技术细节

-   **目录**：`domain/dag.py`（环、类型、字段、受影响节点与分区推导）、`domain/operators/<id>/`（契约、sql、polars、cases）、`domain/reference.py`（宽转长、重叠、用法绑定）、`domain/quality.py`、`domain/run_states.py`（对照契约 pipeline-run）、`domain/versioning.py`（差异、回退、代次）、`domain/semantic.py`（指标 + 维度 → 查询计划、可加性）；`store/`（元数据表、行表、COPY、filter → SQLAlchemy）；`runner/`（job_handler、reconcile_handler）；迁移版本表 `dataproc_alembic`。
-   **行表**：原始 `raw_<短码>`（batch_id, sheet, row_no, cells jsonb, row_hash）；标准 `std_<短码>_s<结构版本>`（_batch_id, _src_row）；基表长表 `ref_<短码>_s<结构版本>`（version_id, 键列, validity daterange，`EXCLUDE USING gist (version_id WITH =, 键 WITH =, validity WITH &&)`，需 btree_gist）；数据集 `ds_<短码>_s<结构版本>`（_v_from int NOT NULL, _v_to int, _month date, _row_key, _row_hash；索引 `(_row_key) WHERE _v_to IS NULL`、`(_month, _v_from)`）。表名由 store 生成，短码白名单校验，绝不把用户输入拼进标识符。
-   **发布事务**：差异写入、`dataset_version`、指针、`generation = generation + 1 RETURNING`、`dataset_partition.partition_gen`、`lineage_edge`、outbox、audit 同一事务。无差异 → publishResult = not_published（注明无变化），代次不变。
-   **唯一性**：同一模型进行中的正式运行 `UNIQUE (pipeline_id) WHERE run_kind='full_run' AND run_state IN ('accepted','running','reconciling')`；跟随运行合并表 pipeline_id 唯一；用法绑定（ref_id, from_date）唯一。
-   **数据库角色**：`dataproc_reader`（只读，10 s，work_mem 16 MB）、`dataproc_runner`（10 min，work_mem 64 MB），迁移用 owner。
-   **查询**：游标绑定 queryVersion、参数摘要、排序、datasetVersion（live 也钉首页版本）、权限摘要、到期时间，HMAC 签名；聚合与总数同样先过权限过滤。
-   **能力**：`titanloom.data.query.execute` · `data.batch.upload` · `data.ingest.save_draft|publish|run` · `data.model.save_draft|preview|dry_run|publish|run` · `data.reference.save_draft|import|check|publish`（effect = future|backfill|revision 必填，backfill 带 from）· `data.dataset.rollback|adopt_revision`（仅负责人，confirm）· `data.snapshot.create` · `data.quarantine.fix|reflow` · `data.field.bind` · `data.query.save`。管家只能 save_draft、preview、dry_run（agentPolicies 写死）。
-   **验收**：M3 出口逐条一条测试；子方案 18.1 场景 1、3、6、7、9–13、17–20（14、16 待 G-ISO）；差异存储基于性质的测试（随机发布 / 回退 / 回补后任意版本读取 = 当次完整计算结果）；发布事务中途杀进程无半个版本、代次不跳；SQL 与 Polars 实现对拍；停掉 Polars 后已发布查询正常；测试数据只用合成人设与合成基表（职业分类、系数、节假日）。
